# ChatGPT Checker Next：兼容修复版

基于 [zetaloop/chatgpt-checker-next](https://github.com/zetaloop/chatgpt-checker-next)
v4.3.4（提交 `6c153995ae03073c90f090ea8f5a8aa41b65762d`），保留原脚本功能。
本地版本：`4.5.0`。修复日期：2026-09-05。

## 修复内容

- **积分统计完整整合（v4.5.0）**：补齐原独立积分脚本的当前周期轮次、积分美元
  估值、周总额美元估值、当前周期每日表格、周期外历史及表格合计、最近活动日期。
  换算单价和历史天数可在设置中保存；Codex 标题旁“积分分析”打开整合后的详情。
  更新后可以停用独立的 Codex Quota Compass，仅运行本脚本。
- **Codex 周额估算（v4.4.1）**：集成仓库内 [Codex Quota Compass](../codex-quota-compass/)
  的积分反推方式。详情中显示当前周期已记积分、每周已用百分比、估算周总额和
  估算剩余，可展开公式与数据时间；设置中有独立开关，沿用白色/深色主题。
- **主题与显示设置（v4.4.0）**：默认白色，可选深色或跟随系统；状态文字、
  表单、开关、进度条和帮助提示统一随主题变化。顶部“设置”可逐项选择显示内容，
  使用油猴存储保留主题和显示偏好；“恢复默认设置”恢复白色、全部显示和统计参数。
  隐藏项目不改变原有功能开关，也不会被后续数据刷新重新打开。
- **详细信息（v4.4.0）**：折叠展示真实订阅、文件库容量、Codex 每日统计和数据读取
  时间。第一次展开时只请求已开启的三项详情，此后手动刷新；同时接收网页自身的
  对应响应，无后台定时轮询。未知字段、空记录、加载失败分别显示；刷新失败时
  明确标注保留的上次结果和成功时间，不将缺失数据当作 `false` 或 `0`。
- **面板排版（v4.3.4.3）**：深色面板采用 328px 响应式宽度和统一字号/行高；
  下拉框预留箭头空间，长模型名支持悬停标题和聚焦展开；Codex 项目名左对齐、用量
  右对齐，取消斜体；统一开关尺寸、行距、分隔线留白。帮助提示可通过键盘访问，
  小屏自动限制宽高并滚动；面板支持键盘打开和 Escape 关闭，尊重减少动画设置。
- **模块发现**：旧脚本只查找 `client-bootstrap.pageLoadResourceHrefs`。实测当前
  ChatGPT 引导数据不再提供该列表，但页面仍有有效的 `modulepreload`。现在依次合并
  引导数据、模块预加载/脚本标签、资源加载记录，去重并限制到同源 `/cdn/assets/*.js`。
- **原生模块连接**：实测即使插入 import map，预加载已经解析过的模块仍会执行原文件。
  常规模型、思考强度、Chat/Work、复制全文现在直接复用页面现有模块的导出函数，
  从当前输入框的 React 祖先/上下文取得对话实例，不再依赖改写模块或重复刷新。
  只从公开模块代码解析并核对所需导出，不执行从网页提取的代码字符串。
- **旧补丁时序**：仅“假装会员”继续使用原来的 import map 路径。缓存存在但
  `document-start` 尚无 `head`/nonce 时，短期 `MutationObserver` 等待插入条件，
  完成或到 `DOMContentLoaded` 后断开。此实验功能在当前预加载构建中仍可能不生效，
  本次没有将其标记为已修复，也无需启用它来查看真实账号信息。
- **年龄验证入口**：原来的 `False` 是把 `show_age_verification_setting` 与 `true`
  比较所得，既混淆了缺失字段和 `false`，也容易被理解为账号的年龄验证结果。
  现在显示“未读取 / 未提供此字段 / 服务端隐藏 / 服务端显示 / 本地显示 / 读取失败”。
  响应早于面板创建时也会保留状态。字段缺失时禁用旧开关，不向响应添加该字段。
- **模型控件**：运行时桥接尚不可用时禁用切换，避免可选但无效的操作。

“年龄验证入口”只诊断入口显示。它不判断年龄、不修改验证结果，也不保证当前
ChatGPT 界面仍使用这个旧字段。入口开关仅在响应包含布尔字段时可用，切换后刷新。

## 新增数据的含义

- **真实订阅**：展示服务端返回的套餐、账户类型、付费订阅状态、计费周期、币种，
  以及返回的续订/取消/到期时间。直接读取原始响应，避免被本地“假装会员”影响。
  使用网页请求的工作区标头确定数据范围；多个账户且无法确认工作区时不猜测。
  工作区标头改变时清空旧详情，并忽略旧请求稍后返回的结果。
- **文件库容量**：已用、上限、剩余和超限状态，单位为 KiB/MiB/GiB。
  如果未提供已用字节，仅在上限和剩余值有效时以两者之差计算。
- **Codex 每日统计**：今日积分/轮次/估值，当前周期的积分/轮次/估值，以及可展开
  的当前周期明细和周期外历史表格，每张表都有合计。历史范围默认近 30 天，
  可设为 1–365 天；为覆盖周周期，实际请求至少包含 8 个 UTC 日期。
  使用 UTC 日期分组，只有明确周期后才区分当前与历史；否则展示近期记录。
  数据可能延迟，缺失日期不补零；只接收按日、无指定其他用户的统计响应。
- **金额估值**：积分乘以设置中的单价。沿用旧脚本默认值 `40 USD / 1,000 积分`，
  可在设置中更改（允许 0），不是官方单价或账单金额。改价立即重算已载入的数据，
  不发网络请求；保存新的历史天数后，已展开的详情会重新读取所选范围。
- **Codex 周额估算**：`本周期已记积分 ÷ (每周已用百分比 ÷ 100)`；估算剩余为
  `估算周总额 − 本周期已记积分`。从代码每周限额的重置时间减去 7 天确定周期，
  仅汇总该周期开始日期至今天（UTC）的记录，不将近 30 天积分全部代入。
  本项复用每日统计，并按需 GET `/backend-api/wham/usage`，同时更新面板原有额度。
  每日表格或估算任一开启时都会读取每日统计和周限额，两项开启仍共用请求。
  首次加载尽量成对读取这两份数据，此后手动刷新，不增加网络轮询。
- **最近成功读取**：仅指当前页面收到有效 JSON 的时间，不是服务端数据的生成时间。
  其他额度仍需网页对应功能触发请求。

周额结果是暂估值，假设统计积分与代码周限额口径一致。百分比可能取整，两接口
可能不同步；在 UTC 日内重置时，首日整天积分还可能包含上一周期的用量。
不推算 Spark 等独立限额；金额仅按用户设置换算。
以下情况暂停估算并显示原因：缺少明确的 7 天限额、比例为 0 或无效、周期时间
缺失/过期、查询日期范围未覆盖周期、当日积分缺失/为 0、记录积分字段无效、
请求失败，或两份数据读取时间相差超过 1 分钟。界面跨过重置点时清除旧估算，
不会自动发出新请求。即使两份数据同时读取，也不保证服务端统计已经同步。

新增 GET 路径来自当前网页公开模块（2026-09-05）：
`/backend-api/accounts/check/v4-2023-04-27`、
`/backend-api/files/library/storage/usage`、
`/backend-api/wham/analytics/daily-workspace-usage-counts`。
账号权限和字段可能不同；这些不是稳定的公开 API。请求限定同源，复用当前登录状态，
不保存凭据、原始账号响应或聊天内容；油猴存储只新增主题、显示偏好和统计参数。

## 与独立积分脚本的功能对应

| Codex Quota Compass | Checker v4.5.0 中的位置 |
| --- | --- |
| 当前用量百分比 | Codex 额度及周额估算 |
| 当前周期积分、轮次、美元估值 | Codex 每日统计及周额估算 |
| 周总额及美元估值、计算公式 | 周额估算 → 计算依据 |
| 当前周期每日表格及合计 | 每日统计 → 当前周期明细 |
| 周期外历史、表格及合计 | 每日统计 → 周期外历史 |
| 最近活动、今日可能延迟标记 | 每日统计及计算依据 |
| `USD_PER_CREDIT` / `HISTORY_DAYS` 配置 | 设置 → 积分统计（改为每 1,000 积分单价） |
| 页头按钮及浮动备用入口 | 统一悬浮面板 → Codex 旁“积分分析” |
| 加载、失败重试、移动端布局 | 统一详情刷新、状态信息及响应式面板 |

数据功能已整合，入口统一到 Checker，没有复制独立脚本的第二个弹窗。
仍保留本修复版对明确周周期、有效字段和数据时间差的检查；未知周期不会像旧脚本
那样退回 5 小时限额或把整个历史查询范围当成本周期。

## 安装与更新

1. 打开 Tampermonkey 中现有的 **ChatGPT Checker Next** 编辑页。
2. 用 [chatgpt-checker-next.user.js](./chatgpt-checker-next.user.js) 的完整内容替换并保存。
   也可以通过本地 HTTP 地址打开该 `.user.js`，在 Tampermonkey 中更新已有脚本。
3. 刷新 ChatGPT，等待当前输入框加载。常规模式应显示“模块连接：原生连接”。
4. 确认面板版本为 `v4.5.0`。“假装会员”需保持关闭才能使用常规原生连接路径。
5. 顶部“设置”选择主题和显示内容；展开底部“详细信息”读取新增数据。
6. “设置 → 积分统计”调整换算单价和历史天数，点击“保存统计设置”。停用油猴中
   原独立 Codex Quota Compass 后，使用 Checker 的“积分分析”入口即可。

保留原 `@name` 和 `@namespace`，用于更新原脚本并沿用设置。`@downloadURL` /
`@updateURL` 设为 `none`，避免上游自动更新覆盖本地修改；此版本需要手动更新。
不要同时运行两个副本。

如需回退，重新安装上游脚本即可。回退会改变脚本版本；不需要删除账号数据。

## 验证

无额外依赖，使用 Node.js 24+：

```powershell
node --check userscripts/chatgpt-checker-next/chatgpt-checker-next.user.js
node --test userscripts/chatgpt-checker-next/tests/compatibility.test.cjs
```

可选实站资源匹配检查：将当前页面公开的 `4813494d-*.js` 和
`conversation-small-*.js` 下载到仓库外的临时目录，再运行：

```powershell
$env:CHECKER_ASSET_DIR = 'C:\path\to\public-assets'
node --test userscripts/chatgpt-checker-next/tests/compatibility.test.cjs
```

测试覆盖当前/旧版资源发现、异常引导数据、资源 URL 限制、早到响应、年龄字段三态、
响应覆盖边界、nonce 等待及清理、原生导出核对、当前对话定位、桥接状态/切换/清理，
以及可选的真实模块补丁匹配。另覆盖设置迁移、订阅工作区选择、数值缺失/零值区分、
请求范围、旧响应丢弃、失败结果保留、按需请求及重试；周额估算另覆盖当前周期筛选、
公式、重置边界、延迟/缺失/异常输入、独立额度隔离及共享请求。另覆盖统计参数迁移
与校验、周期/历史划分、短历史范围不截断周期、金额/轮次合计及缺失值。
实测资源参与时共 25 项测试通过。
公开模块不随仓库分发，测试不保存登录凭据、账号响应或聊天内容。

Chrome 实测：v4.3.4.2 显示“原生连接”，能读取当前模型/思考强度；脚本切换思考
强度后原生按钮同步改变，Chat/Work 切换后原生单选状态同步改变。年龄入口显示
“服务端隐藏”。测试后恢复原始模型、模式和思考强度。面板目视检查无横向溢出，
测试页无 CheckerNext 错误日志。测试不发送聊天消息、不提交年龄验证。
复制全文仅验证本地桥接测试；自动审批拒绝打开已有私人对话，未做实站复制验证。
v4.3.4.3 使用运行真实脚本、由示例响应填充的本地页面检查排版，覆盖 320px 窄屏、
桌面尺寸、长文本、键盘操作和帮助提示边界；未读取私人对话用于视觉预览。
v4.4.0 同样使用本地模拟响应验证白色/深色/系统主题、320px 窄屏、显示项持久化、
全部隐藏后的恢复入口、异步刷新不重新显示隐藏项目、新增详情与失败重试。
新增三个接口的路径已核对当前公开网页代码，尚未验证该账号实际返回的字段。
v4.4.1 使用本地模拟响应验证估算结果、当天零积分、仅 5 小时限额、HTTP 403、
共享每日请求、估算独立开关，以及 320px 窄屏和深色排版。未以模拟估算值代替该账号实测值。
v4.5.0 使用本地模拟响应核对当前/历史明细、表格合计、金额换算、设置校验和持久化，
以及窄屏、快捷入口和刷新交互。整合功能不依赖独立脚本注入；账号实站字段的验证范围不变。

局限：导出识别/旧模块转换仍依赖上游的压缩代码特征，当前对话定位依赖 React
内部结构；后续 ChatGPT 构建可能再次改变这些特征。
此时保留“不匹配”的诊断，不盲目修改未知模块。原脚本自定义模型的 `prompt()`
交互仍保留，前端审计会报告这一既有项。Grok/Codex 专属页面未在本次实测范围内。
